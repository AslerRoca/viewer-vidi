## P9 — Drag a folder or file from the study list onto the Reports panel  ·  2026-11-13
- **Anchor:** `cebfda1` (branch `wip/report-viewer`; code uncommitted at entry time — P7–P9 land together in the next WIP commit)

**Assumption.** The study list already drags image series onto the image panels (`_SmartProxy.mimeData` plus the `drag_state` payload), so the Reports panel only has to accept the same drag and read the path from it. Wrong in one point, found on reading the code: `mimeData` returned `None` whenever the selection was not an image series, so a report folder or a `.txt` / `.csv` file could not be dragged at all — the drag never started.

**What we did.** `drag_state.py`: private mime type `application/x-vidi-paths` (NUL-separated UTF-8) with `encode_paths` / `decode_paths`. A private type on purpose instead of `text/uri-list`: with file URLs a drop outside the viewer would make the file manager copy the dragged folder. `tree_panel._SmartProxy.mimeData` now always returns mime data naming the dragged paths and adds the series payload + `application/x-dicom-series` only when the selection is an image series — image panels behave as before and refuse report drags. `ReportPanel`: `setAcceptDrops(True)`; `dragEnterEvent` accepts only a drag carrying exactly one path (several items, and drags from other applications, are refused rather than half-loaded); `dropEvent` calls `open_source(path)`, the same call as the Open buttons. No handlers on the child widgets: Qt offers a DragEnter to the parents until one accepts and then delivers move/drop to that widget, so drops on the list, the text or the filter field reach the panel. Hint added to the empty panel's source line; README bullet.
Performance at drag start: the tree's series probe (`_make_series_meta`) runs in the GUI thread when a drag begins. On a report folder of ≈7,600 files on the exFAT research drive it stalled ~865 ms. Short-circuiting the sub-directory test and switching to `os.scandir` brought only 794 ms; profiling showed that `os.listdir` alone costs ~390 ms there and ran twice (in `_make_series_meta` and again in `_make_grouped_meta`). The listing is now passed on (`_make_grouped_meta(study_dir, names)`): ~435 ms, i.e. one directory read.
Two testing detours. (a) The new test block segfaulted (exit 139, output lost to buffering; `python -u -X faulthandler` put it in `tree_panel.canFetchMore`): the test helper held a plain `QModelIndex` of the `QSortFilterProxyModel` across event processing, while the tree calls `invalidateFilter()` every 80 ms after background classification and thereby drops the proxy's indexes. The helper now builds proxy indexes on the spot from paths — a test bug, not an application bug. (b) An end-to-end drag did nothing on the `offscreen` platform (the drag loop returned after 0.00 s): its `QOffscreenDrag` is a stub that returns `IgnoreAction`. `QT_QPA_PLATFORM=minimal` runs the real `QSimpleDrag` loop. The end-to-end and profiling scripts lived in the session scratchpad; their results are reproduced here.

**What we got.** `tests/reports/test_reports.py` 71/71 — 7 new checks: the series probe still groups sub-series and a report folder is no series; a dragged report folder names its path and is no series; a drop on the report text opens the folder; a file dropped on the report list opens that file; several items at once and foreign drags are refused; an image panel refuses a report drag; an image folder still drags as a series. Existing suites unchanged: `test_annot.py` 42/42, `test_fixes.py` 44/44 (all three rerun at entry time). Full drag through Qt's drag loop on `minimal` with synthetic data: folder → report text opened its 40 reports, folder → report list opened its 12, folder → image panel was refused and nothing changed. Viewer started on the real display (xcb, 1400×900) with an empty Reports panel: accepts drops, right two panels hidden, panel 770 px wide. Not yet seen: the mouse gesture itself on the real display. Remaining cost: ~0.4 s of hesitation when the drag of a folder with thousands of files begins (one directory read by the drive).

**Try next.** Confirm the gesture on the real display. If the ~0.4 s at drag start bothers: take the series probe out of the drag start (reuse the tree's background classification, or probe on drop). Still open from P7/P8: even split vs. right column + 220 px, report list beside the text, a `--reports <folder>` start argument, full-text search, linking a report to the loaded study by patient ID. Commit the branch (WIP) and decide the merge of `wip/roi-export` + `wip/report-viewer` → `master`.

## P7 — Reports dock: read `.txt` / `.rtf` folders and CSV report exports beside the images  ·  2026-11-11
- **Anchor:** `cebfda1` (new branch `wip/report-viewer` off `wip/roi-export`; code uncommitted at entry time)

**Assumption.** Radiology reports can be read inside the viewer straight from the exports as they lie on disk — a folder with one text file per report, or CSV tables with one report per row and the text as RTF — with no conversion step and no database. Three things had to hold: (1) a table export of several hundred MB can be listed without loading it, by indexing the byte offset of every row and reading rows on demand; (2) a small stdlib RTF converter reproduces the text of the already existing single-file export; (3) reports written from different templates can be formatted from their layout alone (capitals, short heading lines, bullets, `key: value`), so no template is hard-coded. Decided with the user before building: own branch off `wip/roi-export`, a right-hand dock like the Workspace, standalone for now (no link between a report and the loaded images).

**What we did.** `rtf_text.py` (stdlib, no Qt): one tokenizer regex (control word + argument, `\'hh`, control symbol, braces, literal run); a group stack carrying the `\ucN` skip count and an "ignoring" flag; 18 ignored destinations (`fonttbl`, `colortbl`, `stylesheet`, `themedata`, `listtable`, …) plus every `\*` group; `\par` / `\line` / `\tab` / `\cell` mapped to text; `\uN` with its fallback characters skipped; `\'hh` bytes decoded with the code page the document declares (`\ansicpgN`, else cp1252); `clean_text` trims line ends and collapses runs of blank lines.
`reports.py` (no Qt): `scan_reports(path, progress, cancelled)` takes a folder (its own files only; hidden and AppleDouble `._x` files skipped) or one file. `.txt` / `.rtf` → one `ReportEntry` per file, labelled `id · YYYY-MM-DD HH:MM` when the name is `<id>_<YYYYMMDD>-<HHMMSS>`. `.csv` / `.tsv` → `_index_table`: BOM skipped; delimiter = the most frequent of `,` `;` tab in the header line; `csv.reader` fed from a line generator that counts bytes, so the position before each step is the start of that record (also for quoted fields spanning many lines); `csv.field_size_limit(1 << 30)`. The report column is the one with the longest values over the first 20 rows, among the columns named like text / report / Bericht (and not like a date) if there are any; the ID column is the first header matching `pacs_id` / `patient_id` / …, else the first other column; the first date-like column gives the time. Rows identical in every column are indexed once (hash of the row tuple) and counted. Entries are sorted by label, so one patient's examinations are adjacent. `load_report` reads a file up to 2 MB (UTF-8 with cp1252 fallback, UTF-16 by BOM, NUL → "does not look like a text file") or one row at its offset, and refuses the row when its other columns no longer match the index ("has changed since it was indexed"). `parse_report` turns the text into blocks of `(kind, text, value)` lines: `rule` (`===== … =====`), `section` (line in capitals), `sub` (short first line of a block), `label` (`Thorax:`), `field` (`Key: value`), `bullet`, `text`.
`report_dock.py`: `QDockWidget` with Open folder… / Open file…, a source line, a filter field (every word typed must occur in the list line or the header values — the report text is not searched), a `QListWidget` with uniform item sizes, a `QTextBrowser` fed by `report_html()` (the other table columns as a header above the text), Prev / Next and an `n / m of total` counter. Indexing runs in a `_ScanWorker(QThread)` with a cancel flag; its signals carry the worker, so a superseded scan is ignored; `shutdown()` on window close. `main_window.py`: checkable **Reports** toolbar button, Ctrl+Shift+R, the tree's `root_changed` sets the start folder of the dialogs. `style.qss`, README section, `tests/reports/test_reports.py` with synthetic fixtures built in a temp dir.
Before the formatter rules were fixed, the line layouts of the real reports were profiled (two template generations in the data). The real export stayed read-only and outside the repo; only counts and timings were ever printed from it.

**What we got.** On the PET/CT report export the feature was asked for: the single-file folder (≈7,600 `.txt` files) is listed in about 0.1 s; the CSV folder (372 MB, ≈7,700 reports) is indexed in about 2 s in the background, with ≈670 duplicate rows skipped because one table file is a byte-identical copy of another. RTF check against the earlier converter: every CSV row with a `.txt` twin reads back identical (≈7,600 examinations compared, 0 different). Stepping to the next report takes 2–5 ms, filtering 10–20 ms. First run of the new suite 56/60 — two escape glitches in the test file, one racy test helper, and one real weakness (report-column detection on tables whose texts are very short), all fixed; final 61/61, existing suites unchanged at 42/42 (`test_annot.py`) and 44/44 (`test_fixes.py`). Offscreen screenshots with synthetic reports confirmed layout and formatting; both template generations render cleanly. Known limits: the filter does not search the report text; subfolders are not searched; bold / italic of the RTF is dropped (formatting comes from the layout rules); the report column is chosen automatically, there is no manual chooser; with the Workspace dock open as well, the Reports dock falls to its 320 px minimum on windows narrower than about 1900 px.

**Try next.** Use it on the real display (so far seen only offscreen). Candidates if needed: full-text search, linking a report to the loaded study, a manual column chooser. First use showed that the 440 px dock is narrow for reading → P8.

## P3 — DICOM info overlay with collapsible detail groups  ·  2026-07-27
- **Anchor:** `6921c2b`

**Assumption.** Users need to read key DICOM header fields for whatever image is on screen without leaving the viewer. A corner overlay (clinical-viewer style) beats a separate panel/dialog because the info sits where the eyes already are during scrubbing, and costs no layout space.

**What we did.** Three sub-iterations driven by user feedback within one session:
1. **Corner overlay (initial).** New pure-Python `dicom_info.py` (no Qt, matching the `data_model.py` convention): `corner_texts(path, slice_line)` reads a curated tag set header-only via `pydicom.dcmread(..., stop_before_pixels=True, specific_tags=...)` behind a 256-entry LRU cache (`OrderedDict`, move-to-end on hit, popitem on overflow). Returns three formatted blocks — top-left (patient/study identity: name, ID, birthdate/sex, study date/time), top-right (modality · model, study/series descriptions, `Se·Im·slice` line), bottom-right (acquisition params: KVP/mAs for CR/DX, TR/TE for MR, SliceThickness, AcquisitionTime). `ImageCanvas.set_overlay()` + `_draw_overlay()` render four corners in `paintEvent` via QPainter, each block drawn twice (black shadow offset 1px, then theme text `#cdd6f4`) for contrast over both lung fields and black background. NIfTI/plain images fall back to name+format+geometry so behaviour is uniform.
2. **Tag survey (user request "give me a list").** Dumped the full header from a real fixture (`alldata_backup/dicom/original/bpd3_20100419_1.dcm`, AGFA CR) and presented the ~40 available fields grouped (equipment, plate/detector, personnel, image details, identifiers, plus AGFA private dose tags) for the user to choose additions.
3. **Collapsible detail groups (user choice: extras in lower-right, expand on click).** Added `detail_groups(path)` returning five `(title, [lines])` sections — **Equipment / Plate / Staff / Image / IDs** — from ~36 additional tags fetched in the *same* cached read (extended `_ALL_TAGS`). Only populated fields appear; person names de-caret via `_person()`; UIDs shortened to last 14 chars. The canvas bottom-right column now renders **line-by-line** (unlike the other three corners, which draw as one block) so each group header gets a recorded hit-rect (`_ov_header_rects`); a left click toggles expand/collapse (`_ov_expanded` set) and is consumed in `mousePressEvent` *before* the W/L-drag/ROI/TC modes can react, so toggling a group never disturbs windowing. Expansion state lives on the canvas and persists across slice/time scrubbing and series reloads. Headers drawn in accent blue `#7c8fbd` to signal clickability; detail lines in normal overlay text.

**What we got.** Working overlay verified on the AGFA CR fixture. Header-read cost measured **~1 ms cold, ~90 µs cached** (with `_CACHE.clear()` between) — scrubbing stays smooth. All five groups format cleanly: Equipment (`AGFA ADC_51xx`, Station `WQ11PE30I29X`, S/N 1013, SW VIPS1300, institution/dept/address); Plate (`JH04CE (code35)`, `24CMX30CM PORTRAIT`, Sensitivity 400, Exposures 781, Proc code); Staff (Ref/Perf/Read physicians); Image (`DERIVED/PRIMARY`, CHEST, View AP, 12-bit MONOCHROME1, `Rescale ×1 +0 LOG_E REL`, created 2008-09-06 18:39:51); IDs (Acc `3S6OV97JFMHY`, ID issuer + Deident `DICOGNITO`, shortened Study/Series/SOP UIDs). ## P2 — Layer-by-layer input probe; bypass Qt via kernel evdev  ·  2026-07-17
- **Anchor:** `2a91e4f`

**Assumption.** Some layer between mouse and app accumulates tilt detents and flushes only on a full/second detent. Initial hypothesis: libinput's hi-res (v120) wheel handling, or the kernel `hid-logitech-hidpp` multiplier.

**What we did.** Probed every layer of the Linux input stack in isolation (all probe scripts in session scratchpad, results reproduced here):
1. **Kernel (evdev):** raw read of `/dev/input/event7` (G502 via Lightspeed receiver, `hid-logitech-hidpp`, HID++ 4.2) decoding `struct input_event`. 
2. **libinput config:** toggled `libinput High Resolution Wheel Scroll Enabled` 0/1 via `xinput` (Ubuntu 24.04, libinput 1.25.0, xf86-input-libinput 1.4.0, X11 session).
3. **Qt delivery:** probe window logging every `QWheelEvent` (`angleDelta`, `pixelDelta`, phase, source); repeated with `Qt.AA_CompressHighFrequencyEvents` disabled.
4. **X server delivery:** `xev`, watching legacy scroll buttons 6/7.

Findings: kernel emits `REL_HWHEEL ±1` + `REL_HWHEEL_HI_RES ±120` immediately for **every** single click (nothing accumulated; hold auto-repeats at ~100 ms; wheel wobble adds stray vertical ±15 hi-res events). Hi-res toggle: no effect. `xev`: X server delivers every detent 1:1 as button 6/7. Qt probe: isolated clicks **never delivered**; first event of a burst arrives as −240/−360 (2–3 detents flushed at once), proving Qt's scroll-valuator baseline goes stale during idle.
